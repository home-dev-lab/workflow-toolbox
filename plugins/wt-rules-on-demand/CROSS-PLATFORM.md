The judge refuses output inside rollback's discovered store and archive directories for **any** config root: it matches their shared relative path segments on the supplied output parent, every raw link target before normalizing its `..` components, every one-hop symlink substitution, and the final output path. It also rejects any output component matching the store or archive filename patterns shared with rollback. Each path is compared with the selected config's physical store and archive roots. These checks run before creating directories for both `judge` and `extract`, even when a protected intermediate spelling resolves to a harmless-looking destination. On Linux, segment and filename comparisons are case-sensitive. On Windows and macOS, they are case-insensitive (folded segments and case-insensitive patterns), matching the usual filesystem behavior; case-sensitive volumes on those platforms may therefore reject extra outputs. Native `node:path` splitting preserves platform-specific separators and roots. Windows/macOS behavior is source-reviewed, not executed here. An ancestor replaced after its component check but before a later creation operation can still redirect that operation. Between creation of a run directory and opening its file, another process with write access to the parent could also replace that directory with a symlink. Such a same-user process already has permission to write the archive directly, so these creation-window races do not grant the judge access that process lacks; the retained file handle prevents later swaps during model execution from redirecting writes. The test suite uses `fileURLToPath` for filesystem paths obtained from module URLs so Windows drive letters are not duplicated.

Node CLIs use native `node:path` for disk paths. The Function Hooks module and
every transitive import avoid Node builtins, using host capabilities instead.
On POSIX a relative `~` is not shell-expanded by Node: home comes from `HOME`
or `USERPROFILE`; no script interprets a literal tilde path.

Additional dependencies: the rollback summary uses Node `crypto` SHA-256 over
the physical project path to keep separate scope filenames; Node provides it on
Windows and macOS as on Linux. Startup compares rule directories with `realpath`
before reporting unchecked scopes, accommodating macOS path aliases and Windows
short names. The proof CLI uses `stat` (which follows directory links on all three
platforms) to reject a missing transcripts directory. Verdict summaries split
both Windows and POSIX path separators to retain only the file basename.

Trust boundary of the ancestor walk: the engine reads `.claude/rules-on-demand` and `.claude/rules` of every
ancestor of the session root, the same ancestor `.claude/` directories the harness already reads for static
instructions (a session under `/tmp` reads `/tmp/.claude`, as the harness does). It adds no directory the
harness does not already trust; the active config directory stays user scope, and a worktree nested in its main
checkout skips that checkout's directories, as the harness does.
