# Release procedure

Run these steps from `toolkit/` before a plugin release.

1. Run `pnpm certify` (typecheck, lint, quality, full coverage-enabled test in one exclusive suite lease). The receipt under `.lane/certifications/` records admission, start/end load samples and each gate's exit code; it is written before the lease is released. Admission refuses when the one-minute load average is at least `availableParallelism()`; use `pnpm certify -- --allow-high-load` only to record an explicit override. On Windows or an unreadable load signal the receipt says `unavailable` and certification is admitted. Treat this run as the release's single coverage-enabled full-suite invocation. Use this tree's `plugin/bin/wt-suite-lock.mjs` when wrapping a new package script: an older CLI that does not export the inherited marker holds the mutex while the nested script waits on that same mutex, then exits 75 after the normal wait, naming the holder.
   Package scripts and every non-watch Vitest entry take exclusive leases through the filesystem FIFO mutex (`lock.d` and `queue.d`); a lane broker proxies acquisitions through that same mutex. A holder exports `WT_SUITE_LEASE=<domain>|<leaseId>` to its children. Nested invocations in the same domain run covered without waiting: on the filesystem they check the holder record and immediately refuse a stale marker with exit 75; inside a lane they cannot read that record, so they run covered, and the connection-owning ancestor stops its direct child if the broker lease is lost. An unrelated process copying a live marker is a deliberate bypass.
   A run may ask for queue priority as light (`--light` on `wt-suite-lock run` and `with-suite-lease.mjs`; the package scripts for typecheck, lint, quality and the census checks, and a Vitest run whose resolved project selects one to eight files without coverage do; a lane's `vitest run <file>` stays exclusive, since Vitest filters by substring and argv cannot bound the selection): it goes before full-suite waiters queued earlier, and a full suite is passed by at most eight light runs (counted in `light-grants` in the lock directory; while a ticket from an older launcher is queued, everyone orders by ticket number only). This changes only the order of the queue; one holder still runs at a time.
   Direct `node_modules/.bin` and `pnpm exec eslint|tsc|vitest` invocations outside this config, `WT_SUITE_LOCK=0`, a copied marker, and a different state root / `WT_SUITE_LOCK_DIR` are outside the cooperative lock. The CLI and certification hold their lease until the direct child exits and the holder finishes cleanup; non-watch direct Vitest holds through its own process exit, after pool shutdown. A holder that leaves background descendants running is out of contract on every platform: those descendants may overlap the next suite. A holder killed while descendants survive, Windows age-based stale reclaim and macOS PID reuse also limit exclusion. POSIX cleanup never releases a live holder because a time bound elapsed. Vitest watch mode takes no lease. Top-level scripts wait in the FIFO with the standard default wait (`DEFAULT_SUITE_LOCK_WAIT_S`, overridable via `WT_SUITE_LOCK_WAIT_S`) and exit 75 naming the holder and `wt-suite-lock status` on timeout. Interactive commands retain their controlling terminal.
2. Run `pnpm quality:delta`. Copy its Markdown table verbatim into `plugin/CHANGELOG.md` as the release entry's `### Quality` section. Do not compose that section by hand.
3. Improve at least one quality ratchet. A lower maximum is an improvement for size, complexity, duplication, dead code, and cycles; a higher minimum is an improvement for coverage.
4. Run `pnpm quality:baseline`. Review and stage the generated toolkit quality baseline.
5. Create the `release:` commit and tag it `workflow-toolbox--v<version>`.

The release-record guard blocks a `release:` commit when the staged changelog does not add a
`### Quality` section or no baseline ratchet improved since the previous plugin tag. If a measured
release exception is unavoidable, add `gates: quality-skipped — <reason>` to the commit message.
The guard records that escape instead of silently weakening a ratchet.

Coverage includes `toolkit/packages/*/src/**` and `plugin/bin/**/*.mjs`. It excludes tests,
fixtures, generated `dist` output, and fixture executables because those are test inputs or build
artifacts rather than shipped source. Vitest, jscpd, knip, ESLint, and dependency-cruiser are Node
tools and use path APIs in the quality wrapper; the same commands are expected to run on Linux,
macOS, and Windows without POSIX shell pipelines.
